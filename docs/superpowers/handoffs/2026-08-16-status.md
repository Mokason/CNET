## 1. Core attribution layer — COMPLETE

`make attribution` — 105 checks, in `verify`.

The core of the brain-split architecture: the mediator between a creative
hemisphere (LLM proposer) and a logical one (certified capsules). It gives
CNET a memory of *disagreement* between them.

**The key finding is that the blame boundary already existed** in
`acquire_drain`'s pipeline — it is the stage at which an attempt died. The
oracle-evidence gate runs before a single training step, so dying at or
before it means the labels were unusable, and dying after it means the labels
were fine and the student could not fit. Attribution records the stage; it
does not invent a judgement.

Two posteriors per `(proposer, goal signature)`, both Laplace-primed so a cold
key reads 0.5:

- `proposer_trust` — are this proposer's labels usable here? `SYSTEM_FAULT`
  sits in the numerator, because it is explicitly *not* the proposer's fault.
- `signature_yield` — given usable labels, does this signature certify at all?

Today both collapse into a single `certify_failed` count, which cannot tell
"the creative side is hallucinating" from "the logical side can't learn this".

**It proved itself on a real failure during development.** The acquire fixture
fails on this box, and the sink attributed it `proposer_fault=0
system_fault=1, trust=0.667 yield=0.333` — proposer correctly not blamed,
signature correctly flagged.

Report-only is a *property*, not a claim: the gate runs the same acquisition
twice, with and without the sink, and asserts all 13 acquire-visible outcomes
are identical.

Also included: a `CNET_ATTRIB` sidecar (fuzz-gated — 72 byte-flips, 73
truncation lengths, 0 crashes, every refusal leaves state untouched),
split-conformal calibration of proposer confidence, an append-only event log,
and `attrib_report`.

Deliberately out of scope for v1: no throttling, no gating, no conformal
enforcement, no change to oracle selection.

## 2. QAT modern block — COMPLETE

`make qat_block` — 54 checks, in `verify`.

`cce_transformer_qat` was GPT-2 shaped and could not express any modern
checkpoint. It now composes RMSNorm, RoPE, GQA, SwiGLU and optional-bias.

| config | gradcheck rel err |
|---|---|
| legacy (zero-init) | 3.155e-03 |
| RMSNorm | 1.430e-03 |
| RoPE | 3.737e-03 |
| SwiGLU | 1.791e-03 |
| GQA | 2.313e-03 |
| no-bias | 1.023e-03 |
| **full modern endpoint** | **2.303e-03** |

All under the 5e-3 bar, and the composed block trains: loss 3.1421 → 0.0096.

**Zero-init config still reproduces the legacy model bit-identically** —
anchor `logit[0] = 0.0263260156`, unmoved across all five ops.

Two decisions worth carrying forward:

- **GQA keeps fused QKV as ONE matrix** with variable width
  `QKVW = D + 2*kvh*hd`. Under MHA that is exactly `3*D` with byte-identical
  Q/K/V offsets, so legacy numerics are safe *by construction* rather than by
  being tested for. Do not split it into three matrices.
- **RoPE pairing is pinned to half-split** (HF Llama/Qwen) and switchable. It
  is gated *algebraically* — norm preservation and relative-position
  invariance — because gradcheck cannot catch a wrong pairing: any consistent
  rotation differentiates correctly.

**A live hole was found and closed.** The gradcheck walked a hand-built
`P* groups[128]` with `if (ng + 12 > 124) break;`, and `pos_emb` was never in
it. Registration is now a side effect of allocation. Fixing it exposed three
*more* hardcoded parameter walks — `tr_zero_grads`, the Adam update, and
`free()` — all now registry-driven. A completeness gate compares the
registry's parameter count against an independently derived total across 8
configs, and was verified to have teeth: deliberately unregistering one group
produces 13 failures.

## 3. Mojo kernel bridge — C SIDE COMPLETE, MOJO SIDE UNBUILT

`make mojo_bridge` — in `verify`.

Mojo integrated as an **optional, never-load-bearing** kernel layer behind a
hand-written C ABI. No Python anywhere.

Goal: one kernel source targeting NVIDIA *and* AMD, to collapse the problem
that `cce_clgemm` is the only GPU backend carrying backward/STE GEMMs while
`hipgemm` and `cudagemm` are forward-only. **The CPU trit kernel is stage 1
and is not the goal** — it proves the toolchain on the safest surface. GPU is
stage 2 and gets its own spec.

Built and gated:

- `cce_trit_matmul_c` extracted verbatim from `cce_block_forward`;
  `trit_bench` confirms no bits moved.
- `cce_mojo_dispatch.c` is the only file that knows Mojo exists.
- **Default OFF** — needs `CNET_HAVE_MOJO` compiled in *and* `CNET_MOJO=1`.
- The harness proves itself C-against-C over 10 shapes × 2 modes before it
  can ever see a Mojo kernel. Anchor `c88ffc1c1ef0f50a`.
- `MOJO_PROBE` mirrors `CURL_PROBE`: absent toolchain means the Mojo branch is
  preprocessed out and nothing changes.

**`mojo/trit_matmul.mojo` has never been compiled.** The file says so at the
top. `abi("C")` placement and the `exp` import are inferences — the 1.0 docs
cover C→Mojo but not the export direction, and Mojo reached 1.0 on
2026-08-12. Expect to correct syntax on the first Linux build.

## 4. Windows build unblocked

`make acquire`, `make attribution`, `make qat_block`, `make mutate` and
`make transformer_qat` now build on the Windows box; several could not build
at all before.

- `src/base.c` — `<fcntl.h>` was inside the non-Windows branch. **Also added
  `O_BINARY`**: the CRT was translating `\n` on write, which would corrupt the
  `.cnb` seal digest. That was a latent correctness bug, not just a compile
  error.
- `src/router/registry.c` — `_mkdir` without `<direct.h>`.
- `Makefile` — `-lcurl` was unconditional in global `LDFLAGS`, so a box
  without libcurl could not link *any* target. Now probed.
- CCE layer — libcurl made optional behind `CNET_HAVE_CURL` (it backs only the
  HTTPS download path; on-disk checkpoints are unaffected), the POSIX-only
  `CNET_GGUF_MMAP` fast path guarded, and `mkdir`/`fsync` shimmed.

## Known-red and unverified

Stated plainly rather than buried.

- **`make acquire` fails** at section 4: the student certifies 15/16
  exemplars → `certify_failed`. Pre-existing and untouched. **Not codegen** —
  reproduced identically at `-O0` with no `-march=native`. It is the MinGW
  libm producing a different SGD trajectory than glibc. Diagnose with
  `CNET_CERT_DIAG=1`.
- **The Mojo kernel has never been compiled or benchmarked.** No performance
  claim is made for it. Expect it to be *slower* than the 27.9× C kernel —
  it is a naive triple loop written to match the C accumulation order, and its
  job is to prove the bridge, not to win.
- **Only the AMD half of the Mojo goal is verifiable** on current hardware.
  The NVIDIA card is in the Windows box, which cannot run Mojo (no native
  support; WSL2 declined). "Compiles for both" and "verified on both" are
  kept as separate claims.
- **Bit-identity for the Mojo kernel is a float problem**, not an integer one.
  The kernel does `out[o] += a * (float)codes[o]` with float `a`, so
  byte-equality needs matching accumulation order *and* matching FMA
  contraction across two compilers. If the equivalence gate fails, measure and
  record the divergence before loosening the bar.

## Governance note

Mojo's compiler remains proprietary; open-sourcing is committed for Fall 2026.
Qualcomm closed its acquisition of Modular on 2026-07-28. The bridge is
designed so that if any of that goes wrong, deleting `mojo/`, one Makefile
stanza and one `#ifdef` returns the tree to exactly its prior behaviour — the
C path never stopped being the real implementation.
