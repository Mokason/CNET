# Ordered usability checkpoint and remaining product boundary

## Decision

Make the existing everyday Unicode workflow demonstrably usable before adding
another model, capsule format or inbox. Keep grammar ownership and independent
native certification. Measure the learned fallback separately from total hybrid
accuracy. Do not promote grammar-off inference on an exposed cohort.

Native task rehearsal, paired diagnostic and shared language repair are the
first three slices. The fourth is a reviewed local checkpoint and explicit
rollout handoff, not live activation. The fifth is gated on genuine verified
experience and useful task choices; implementation authority cannot attest
human origin, approve a source on the owner's behalf or fabricate useful gain.

## Evidence and safety

The private deployment exercises missing evidence, imported pinned external
Unicode data, explicit synthetic-test approval, canonical capsule probation,
verified offline upper/lower values, and unchanged coverage refusal. Learned
proposals never supply training answers. Review found additional wrong-ready
cases outside the passed historical cohort; RED tests precede span, action and
direction guards. See the [dated result](../result/cnet_task_usability_20260910.md).

The named-operand validator uses one canonical normalization pass with strict
unknown-prose refusal. Rechecking raw text had lost valid shown-as ambiguity.
The learned fallback masks exact recognized spans, preserves occurrence count,
rejects multiple actions/directions, and cannot mint ready without a direction.
These constraints deliberately limit the specialist; they are not unrestricted
language understanding. No model corpus or certification floor was changed.

## Opt-in rollout sequence (not executed)

1. Finish source checkpoint review and inspect its exact diff. Preserve the
   existing live release, private policies, source pins, ledger and service units.
2. Use a new private schema-3 installation following
   [the existing contract](../docs/AUTONOMOUS_LEARNING.md) and
   [task workflow](../docs/VERIFIED_TASK_CORE.md). Do not overwrite a schema-2
   ledger or replace DLLs inside a pinned deployment. Freeze fresh managed/native
   hashes together; keep the current live owner running until a cutover is approved.
3. Run the documented synthetic task/approve/tick/verify rehearsal against that
   installation, with teacher/self-answer disabled and unchanged budgets. Require
   `verified` native values, accepted probation, coverage refusal, and retained
   receipts. Synthetic approval here is not approval for new live sources.
4. Before changing any bridge/service, explicitly authorize the target service,
   new installation and cutover. Quiesce its owner, preserve the old routing and
   release pins, then test the new route. No source or ledger migration is implicit.
5. On failed startup, wrong result, broken coverage or unexpected demand, stop
   the new owner and restore the preserved old route/release. Keep the new private
   ledger and receipts for diagnosis; do not copy its data into the old ledger.
   Exact service commands require the current live configuration, which this
   source-only checkpoint neither modified nor re-certified.

## Broader product sequence still open

Existing capture exports have no eligible episodes. Use the existing capture
origin review and task inbox rather than a second evidence store. Owner review
must distinguish real human requests from tests/automation; retain whole
chronological windows, heartbeat/continuity checks and independently verified
native outcomes. A source approval does not attest human origin.

Then choose one useful multi-step workflow with approved independently checkable
inputs and outputs. Extend existing capsule compositions, and invalidate/check
dependent compositions when a pinned source changes before activating updates.
Existing source conflicts and probation controls are prerequisites, not proof
that frequently changing real-world sources are solved.

Only eligible native trajectories can justify the AMD worker campaign. Preserve
the native four-family, equal-budget headroom and paired gain checks; synthetic
language scores and GPU utilization are not allocator improvement. No GPU fit,
live capture export, human attestation or external source addition was executed
for this checkpoint. These require evidence/owner choices, not relaxed gates.
