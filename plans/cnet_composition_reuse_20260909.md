# Verified composition reuse — September 9, 2026

## Contract and scope

Export the capsule subset selected by one successfully verified typed request,
then reopen it offline using the existing planner and per-hop coverage guards.
This is an ordinary inventory of existing capsule directories, not a workflow
language, fused kernel, answer cache, new packaging format or training data.
The successful execution selects dependencies; it supplies no training labels.

Use the existing snapshot publisher for byte-preserving, owner-controlled,
bounded copies and content-addressed, no-clobber publication. Before publication,
reopen the staged subset, compare selected capsule identities and replay the
request with the same verified value and route receipt. Refuse missing assets,
identity drift, invalid paths, changed results or an uncovered request. Sources
must be owner-stable during export; this is not a transaction against malicious
same-owner writers. Source-pinned capsules retain their freshness requirements;
offline reuse does not override expiry or make unavailable sources available.

## Acceptance boundaries

Route length remains at most eight; export selects at most eight distinct
capsules. Existing inventory/file/byte and search budgets are not increased.
Different covered inputs can be replanned through the exported subset. It does
not promise one fixed route for every input, export unused alternative paths,
or certify a broader composed domain from one successful request.

No live services, frozen soak, genuine capture, schemas or allocator gates change.
Independent frozen paraphrase evaluation, richer task inputs, dependency-aware
source replacement and measured AMD task-selection improvement remain separate.
