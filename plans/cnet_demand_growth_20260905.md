## Ordered slices and acceptance

1. Test isolation: authority builds the ROE front-door executable without running
   its production-relative seeder. Tests use private roots; a sentinel catalog
   survives verification unchanged. RED dry-run dependency check, then green.
2. Intent grammar: case/whitespace variants normalize grammar keywords (not
   interface tags); recognized invalid requests clarify, never fall through.
   RED adapter and socket regressions, then existing front-door proof.
3. Covered search: use bounded breadth-first states of (typed port, actual
   value), execute every edge through the existing strict guarded executor.
   Preserve the eight-hop ceiling; an uncovered value cannot blacklist an
   otherwise usable suffix. RED shared-suffix reproduction; cycles/OOD tests.
4. Mandatory historical regression: derive expected reachable task results by
   joining the existing sealed contract labels, never by treating BTN answers
   as training labels. Before every CLI publication, require the candidate to
   preserve these direct and composed obligations, checking both inventories'
   label closure filtered through actual coverage. Refuse on missing evidence,
   disagreement or budget exhaustion. Reuse the capsule format, with no second
   packaging system or mutable historical-answer cache. RED shortcut regression
   must fail even when the submitted evaluation omits the old composed task.
5. Demand ingestion: typed capsule misses may enqueue only normalized tags and
   unsigned values in an opt-in owner-local bounded demand directory. No answer
   text, arbitrary commands, URLs or claimed provenance travel in a demand.
6. Evidence acquisition: an owner-approved finite tool policy maps domains to
   bounded exact arithmetic operations. An independent tool generates labels;
   the existing curriculum admits immutable capsules with mandatory historical
   checks. Unknown policy, overflow and invalid evidence refuse. No new network
   integration or automatic LLM-as-ground-truth path.
7. Integration proof: initial socket miss -> demand -> trusted tool -> existing
   queue -> certification -> fresh socket answer; repeat is idempotent, prior
   tasks remain correct, unknown domains refuse. Run full isolated verification
   and capability/portability gates, document exact measured scope.

## Trust boundaries and limits

Requests express demand, not truth. The owner-local policy is authority to run
only explicitly implemented pure tools over bounded integer domains. It cannot
contain shell code. Teacher/tool labels remain separate from model output.
Per-hop coverage and contract certification grant serving authority. Candidate
replay cannot lower floors to fit a task. Search and replay budgets fail loud.

This slice automates finite, policy-supported evidence acquisition; arbitrary
language interpretation, unknown-domain teacher discovery, unseen-input
generalization, large-inventory throughput, power-loss recovery of all legacy
writers and authentication for remote policy uploads remain separate gates.
