### D3 — `cnetd` never exits on SIGTERM; `cnet_core_e2e` hangs after passing

`tools/cnetd.c` installs its handlers with `signal()`:

```c
static volatile sig_atomic_t g_stop = 0;
static void on_sig(int sig) { g_stop = 1; }   /* line 74  */
...
while (!g_stop) {
    cfd = accept(sfd, NULL, NULL);            /* line 1226 — blocks */
...
signal(SIGINT,  on_sig);                      /* line 1254 */
signal(SIGTERM, on_sig);                      /* line 1255 */
```

On glibc, `signal()` carries `SA_RESTART`, so the blocked `accept()` is **restarted**
after the handler runs instead of returning `EINTR`. `g_stop` is set but the loop
condition is never re-tested, and the daemon sleeps in `accept()` indefinitely.

`scripts/cnet_core_e2e_smoke.sh` does have a correct `trap cleanup EXIT`, but cleanup
is `kill "$PID"; wait "$PID"` — and that `wait` blocks forever on a daemon that will
not die. The gate printed:

```
CNET_CORE_E2E_PASS pass=10 fail=0 held=bonsai:8081 core_middle=1
```

…and then hung. It scored PASS at 254s only because the analysis connected to
`/tmp/cnetd-core-e2e-114908.sock` by hand; that single connection woke `accept()`, the
loop re-tested `g_stop`, and the process exited immediately — confirming the
diagnosis. Left alone it would have burned the full CI timeout and been recorded FAIL
despite all ten checks passing.

Signal state of the live process while wedged (`/proc/<pid>/status`) — TERM is caught,
not ignored, which rules out a masking bug and leaves the restart as the cause:

```
SigIgn: [3, 13]        SigCgt: [2, 15, 33]        State: S (sleeping)
```

Secondary, **unverified**: the probe reply to a fresh `{"q":"ping"}` came back with
content for the *previous* request (`"You asked about compute crc8 of unknown blob
zz99nofill…"`). That may be the `utter_probe` skill legitimately quoting the last miss
rather than a response-ordering fault — flagging it only as worth a look.

## D1 — Mojo optional again

- `MOJO_LIB` / `MOJO_LDFLAGS` switched to deferred `=`, so `BIN_DIR` resolves at
  use time: `MOJO_LIB` is now `bin/libcnet_mojo.so`, not `/libcnet_mojo.so`.
- `-DCNET_HAVE_MOJO` removed from global `CFLAGS` and moved into a new
  `MOJO_CFLAGS`, applied only by `mojo_bridge` and `mojo_bench`. The other 101
  `$(CCE)` recipes compile the C fallback branch and link clean.
- New gate `make mojo_optional` (`tests/test_mojo_optional.sh`) — asserts
  `MOJO_LIB` sits under `BIN_DIR`, that the dispatch layer links under global
  CFLAGS with no Mojo symbols, and that `-DCNET_HAVE_MOJO` is not global.
  RED before (3/3 fail), PASS after.

**Also fixed: the Mojo kernel had never compiled.** With D1a corrected, the
build reached `mojo/trit_matmul.mojo` and it did not parse — the file carried an
"UNVERIFIED SYNTAX / has NEVER been compiled" banner and every open question in
it was real. Corrected against Mojo 1.0.0: `fn` → `def` (removed in 1.0),
`std.`-prefixed imports, `UnsafePointer` dropped from imports (prelude) and
given explicit `ImmUntrackedOrigin` / `MutUntrackedOrigin` origins, and
`@export` paired with the `abi("C")` effect placed after the argument list and
before the return arrow. `nm -D` confirms `T cnet_mojo_init` and
`T cnet_mojo_trit_matmul`. Banner replaced with the verified findings.

**New finding recorded, not papered over:** with a real Mojo kernel now
runnable, C-vs-Mojo byte-equality **fails** — 12 of 20 shapes, max **26 ULP**,
max relative **1.97e-06**. Two controls show the divergence is on the *Mojo*
side (rebuilding C with `-ffp-contract=off` changed nothing; splitting the Mojo
expressions changed nothing), refuting the spec's own guess that GCC's
`-ffp-contract=fast` was responsible. Written into §2.2.1 of the bridge spec,
which pre-authorised exactly this ("the measured divergence and its cause are
written into this spec. The bar is not loosened silently"). **No bar was
lowered**: the Mojo path remains off by default, and the C path's byte-equality
requirement is untouched. What is now on record is that `CNET_MOJO=1` is not a
behaviour-preserving switch.

## D3 — `cnetd` honours SIGTERM

`signal()` replaced with a new `install_stop_handler()` using `sigaction` and
`sa_flags = 0` — deliberately no `SA_RESTART` — so the blocked `accept()`
returns `EINTR`, which the serve loop already handled correctly. The loop was
never the bug; the handler installation was.

`scripts/cnet_core_e2e_smoke.sh` cleanup additionally bounded: wait up to 5s,
then escalate to `SIGKILL` with a warning, so this gate can never again hang on
`wait` if the daemon regresses.

New gate `make cnetd_sigterm` (`tests/test_cnetd_sigterm.sh`) — asserts an
**idle** daemon (the case where `accept()` is blocked) exits within 5s, unlinks
its socket, and is reapable. RED before (3/3 fail, 5.0s timeout), PASS after
(**0.1s**).

Measured effect on the board: `cnet_core_e2e` went from **254s** — and that
only because the socket was poked by hand; unattended it was a 900s timeout →
FAIL — to **3s**.
