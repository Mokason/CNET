## What is operational

Four exact requests use the separate existing learning control plane:

| Request | External-source contract |
| --- | --- |
| `unicode upper 181` | Explicit uppercase field: 924 / U+039C |
| `unicode lower 65` | Explicit lowercase field: 97 / U+0061 |
| `unicode category DIGIT_ZERO` | General_Category: Nd |
| `unicode bidi DIGIT_ZERO` | Bidi_Class: EN |

The fixed Unicode 17 excerpt independently supplies labels. Missing explicit
case fields and unknown symbolic names abstain. The native-certified result,
typed identity and independent value must agree before a verified reply is
rendered. A miss records demand once and abstains; the adapter never substitutes
the external label for an unlearned answer. There is no arbitrary source import,
shell command, teacher fallback, web-prose learning or allocator activation.
This is four finite datasets, not unrestricted domain learning or a full Unicode
algorithm. Main peer/MCP behavior remains separate and unchanged.

Only remotely verified capture-owner DM messages can use the bridge. Persistent
capture and deduplication precede one downstream attempt. Malformed commands
cannot delegate to legacy mapping or main-peer fallback. Malformed/failed native
results latch the bridge and attempt durable pause; subprocess timeouts remain
unknown without automatic retry. See [the operator contract](../docs/DISCORD_VERIFIED_LEARNING.md).
